# TB 재고관리 (템버린즈 소품·집기 재고)

에이도스 스튜디오가 운영하는 템버린즈 매장용 소품·집기 재고관리 웹앱.
사용자는 비개발자(대표 1인)이므로 설명은 쉬운 한국어로, 변경은 작고 확인 가능하게 한다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `index.html` | 매장 매니저 화면(재고 조회, 출고 요청). 다국어 지원 |
| `admin/index.html` | 관리자 화면(재고 관리, 주문 승인·반려·출고, 시트 동기화) |
| `sw.js` | 서비스워커. 네트워크 우선, 실패 시 캐시 |
| `manifest.json`, `manifest-admin.json` | PWA 설정(매장용·관리자용) |
| `icons/` | PWA 아이콘 |

- 빌드 도구 없음. HTML 파일 하나에 CSS·JS가 모두 들어 있는 단일 파일 구조.
- 호스팅: GitHub Pages, `main` 브랜치가 곧 배포본. `main`에 머지되면 바로 실서비스에 반영된다.
- 외부 라이브러리: Firebase JS SDK 10.12.0(app, firestore, auth), SheetJS(xlsx) 0.18.5는 매장 화면에만 로드 — CDN.
- 이 앱은 `gm-stock/gm-stock.github.io`(젠틀몬스터)를 바탕으로 만든 쌍둥이 앱이다.
  한쪽의 버그 수정이나 기능은 다른 쪽에도 필요한지 사용자에게 확인한다.

## 데이터 (Firebase 프로젝트 `tb-stock-management`)

| 컬렉션 | 내용 |
| --- | --- |
| `items` | 재고 품목 |
| `orders` | 매장 출고 요청(`storeName`, `items`, `status` 등) |
| `stockLogs` | 재고 변동 기록 |

- 주문 상태 값은 한국어 문자열이다: `검토중`, `승인`, `준비중`, `출고대기`, `출고완료`, `반려`, `취소`.
  영어로 바꾸지 않는다(기존 데이터와 깨짐).
- `STOCK_HELD`(검토중~출고완료) 상태의 주문은 재고를 점유한다. 반려·취소 시 재고가 복원된다.
- Google Sheets 동기화는 Apps Script 웹앱 URL로 호출한다(`admin/index.html` 안). URL은 바꾸지 않는다.
- 매장 목록 자동완성: `STORE_LIST` 배열(`index.html`, `admin/index.html` 양쪽에 있음). 2026-10-21 사용자 요청으로 비워 둠(젠틀몬스터 목록이 들어가 있었음). 템버린즈 목록을 받으면 양쪽에 넣는다.

## 로그인·권한 (2026-10 도입, 젠틀몬스터 앱과 같은 방식)

- Firebase Auth 이메일/비밀번호 로그인. `admins` 컬렉션(문서 ID = 이메일, `role`: `owner`/`manager`), `stores` 컬렉션(매장 공용 계정).
- 템버린즈에는 아직 담당자(manager)를 등록하지 않는다(사용자 요청, 추후 등록).
- 보안 규칙 원본·테스트는 `firebase/` 폴더(기록용). 게시는 Firebase 콘솔에서.
- 템버린즈 관리자 화면에는 '일괄 발주' 탭이 없다(젠틀몬스터에만 있음).

## 디자인 (2026-10 리디자인, 젠틀몬스터 앱과 동일)

- 색은 CSS 변수(`--bg`, `--ink`, `--accent`, `--low`, `--ok` 등)로만 쓴다. 각진 모서리, Roboto + 나눔고딕.
- 기본 밝은 화면, 밝기 선택은 localStorage `gm-theme`에 저장. 헤더는 항상 검정.
- 컬렉션 색: 템버린즈는 정해진 색이 없어 컬렉션 이름마다 팔레트 색이 자동으로 고정 배정된다(`collVars`).

## 다국어 (`index.html`)

- `I18N` 객체에 언어별 문구가 있다: `ko`, `en`, `ja`, `zh-CN`, `zh-TW`.
- 선택 언어는 localStorage `gm-lang`에 저장된다(GM 앱에서 가져온 키 이름 그대로).
- **번역하지 않는 것(원문 유지)**: 상품명, 매장명, 컬렉션명, 소재.
- 새 문구는 5개 언어 모두에 키를 추가한다. 번역 문구는 먼저 표로 보여주고 확인받은 뒤 반영한다.

## 작업 규칙 (반드시 지킬 것)

1. 수정 전에 무엇을, 어디를, 왜 바꾸는지 계획을 먼저 보여주고 승인받는다.
2. 큰 수정은 한 번에 하지 말고 단계로 나눈다. 한 단계 = 한 가지 변경.
3. 매 단계 후 문법 검증을 실행한다:
   `python3 .claude/scripts/check-html.py index.html admin/index.html && node --check sw.js`
4. 요청 범위 밖의 코드는 정리·리팩터링하지 않는다.
5. Firestore 컬렉션 이름, 필드 이름, 상태 값을 바꾸는 변경은 반드시 먼저 물어본다.
6. 변경은 `claude/`로 시작하는 브랜치에 올리고 PR로 제안한다. `main`에 직접 푸시하지 않는다.
7. 화면에 보이는 변경이면 PR 설명에 확인 방법을 적는다.

## 알려진 사항

- 서비스워커 캐시 버전: `sw.js`의 `CACHE_NAME`(현재 `tb-stock-v2`). 큰 화면 변경 시 올린다.
- 사용자는 2026-10-21부터 "보안상 꼭 본인이 해야 하는 것만 빼고 PR 머지까지 직접 처리"하도록 맡겼다. 단계별 PR·검증 규칙은 그대로 지킨다.
